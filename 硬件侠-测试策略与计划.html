1. 测试范围

硬件侠是一个垂直于电脑配件的 C2C 二手交易平台，采用 DDD 微服务架构，共 15 个微服务域、9 个逻辑数据库、49 张数据表。核心差异化能力为「平台验机 + 担保交易 + 7天退换」。

1.2 不在测范围

  • 第三方服务内部实现（微信/支付宝支付网关、快递100 API、阿里云内容安全、公安实名API）— 通过 Mock/Stub 验证集成
  • 基础设施部署与运维（K8s、Nacos、RocketMQ集群管理）— 仅验证服务在基础设施上的行为
  • 数据仓库 ETL 与 BI 报表（ClickHouse OLAP 部分仅做接口验证）

5. 准入/准出标准

5.1 测试准入标准

  • 需求文档评审通过（PRD + 流程图 + HLD + LLD）
  • 开发提测单已完成自测并附自测报告
  • 测试环境部署完成且冒烟测试通过
  • 测试数据准备完成（造数脚本就绪）
  • 所有 Mock/Stub 服务可用

5.2 测试准出标准

  • P0 用例 100% 通过，P1 用例 100% 通过
  • P2 用例通过率 ≥ 95%
  • 无未关闭的 P0/P1 缺陷
  • 性能指标全部达标（首屏≤2s，搜索≤800ms，消息≤2s）
  • 安全测试无高危漏洞
  • 核心链路 E2E 测试 100% 通过
  • 三方对账（担保/钱包/流水）无差异

6. 风险评估与应对

风险项风险等级影响应对措施
Redis 预扣与 MySQL 实扣时间差导致超卖高资金损失、用户投诉Lua原子操作+乐观锁双重保障；MQ消费失败重试；每日对账
TCC 悬挂/空回滚处理不当高资金不一致Cancel先到标记+Try检查标记；空回滚幂等处理；每日对账
支付回调验签失败或重复回调高重复扣款/未支付强制验签+幂等键去重+定时主动查询兜底
验机报告 SHA-256 签名被绕过高信任体系崩塌报告表仅INSERT权限；盐值存Nacos加密配置；前端签名验证
MQ 消息丢失导致事件未消费中状态不一致Outbox Pattern+本地事务；消费幂等；定时补偿
ES 不可用导致搜索降级低搜索体验下降降级到 MySQL 模糊查询；ES 集群3节点高可用
机审不可用导致UGC堆积中审核延迟降级为全部人工审核；禁止直接放行
新号交易限制误伤正常用户低用户体验差限制仅大额交易；24h后自动解除

8. 核心业务链路覆盖

Flow 1：核心交易主链路

浏览/搜索 → 查看验机报告 → 下单付款 → 担保托管(冻结) → 通知卖家发货 → 卖家发货 → 物流配送 → 买家确认收货 → 担保放款(扣手续费) → 评价/售后

Flow 2：商品发布与验机链路

填写商品信息 → 勾选验机同意 → 提交发布(审核中) → 平台审核(机审+人审) → 寄送验机中心 → 12项检测 → 生成报告(SHA-256签名) → 上架在售

Flow 3：售后退款链路

买家发起售后(7天内) → 选择类型(仅退款/退货退款/换货) → 平台审核 → 卖家决策(同意/拒绝) → 买家寄回 → 卖家确认 → 退款/换货 → (拒绝时)平台仲裁

Flow 4：资金托管链路

买家付款(余额/微信/支付宝) → 担保账户冻结 → 确认收货放款(扣1%手续费) → 卖家可用余额 → 卖家提现(T+1) / 售后退款 → 原路退回买家
