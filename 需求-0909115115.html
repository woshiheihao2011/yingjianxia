残留问题清单

P1-01 搜索功能异常（路由守卫冲突） P1 未修复
访问/search?q=显卡时，页面标题"搜索-硬件侠"正常加载且搜索框已填入"显卡"，但页面持续显示"搜索中..."后自动跳转至/audit?type=1审核中心，无法展示搜索结果。控制台存在Vue Router导航守卫next()弃用警告。

根因分析：这不是搜索接口本身的问题，而是前端路由守卫（navigation guard）在/search路由上触发了异常重定向。搜索请求可能被路由守卫拦截后重定向到了/audit?type=1。
控制台错误: Vue Router navigation guard next() deprecation warning 跳转路径: /search?q=显卡 → /audit?type=1
影响范围: 买家搜索全链路 建议排查: 1. 前端router/guard中对/search路由的守卫逻辑 2. 是否存在路由匹配冲突（/search和/audit的路由定义） 3. next()调用方式是否符合Vue Router 4规范 负责域: 前端
P1-02 /product/{id}商品详情异常（后端404但前端渲染占位数据） P1 未修复
直接访问/product/1时，后端返回code: 2010, message: "商品不存在或已删除"，但前端未正确处理该错误，仍渲染了占位数据（价格¥0、图片"暂无图片"、卖家"未知店铺"）。/product/2同样报错，UI渲染"商品不存在或已下架"提示但仍显示占位数据。

根因分析：ID=1和ID=2的商品在数据库中不存在或已被删除（状态为已删除）。后端正确返回了错误码2010，但前端未拦截该错误状态，仍使用默认/空值渲染了商品详情组件。
后端返回: {code: 2010, message: "商品不存在或已删除"} 前端行为: 未拦截错误，仍渲染占位UI（¥0/暂无图片/未知店铺）
影响范围: 商品详情页直接访问 建议: 1. 前端在商品详情接口返回非成功code时，应展示"商品不存在"提示页而非占位数据 2. 或确保/product/1对应有效商品数据 3. 建议前端拦截code=2010跳转404页面或空状态组件 负责域: 前端 / product-service
P2-01 审核子页面仅1/5独立（4个仍跳转/audit） P2 部分修复
/admin/products已独立展示商品审核页面（统计卡片+标签切换+商品列表+操作按钮），该页面已修复。但其余4个子页面仍未独立：
  • /admin/inspection → 重定向至/audit?type=1，未展示验机审核
  • /inspection → 重定向至/audit，main区域为空
  • /admin/orders → 重定向至/audit?type=3，main区域为空
  • /admin/users → 重定向至/audit?type=3，main区域为空
影响范围: 验机审核、订单管理、用户管理功能 建议: 1. 参照/admin/products的独立实现方式，为其余4个子页面开发独立组件 2. 或在/audit内通过子路由Tab区分不同审核类型 3. 验机审核(/inspection)可对接inspection-service 负责域: 前端 / audit-service / inspection-service
